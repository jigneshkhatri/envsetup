Reproduce a Linux workstation
from its exported state.

EnvSetup captures the complete state of a workstation — packages, dotfiles, cloned repos, fonts, systemd services, and anything you declare by hand — into a plain-text, git-friendly project. Point it at another machine and it gets you back to that state: safely, predictably, and repeatedly.

#

philosophy

Rebuilding a workstation by hand means retracing dozens of steps that were never written down. EnvSetup exists to make that reproducible instead — and it stays disciplined about how.

# human-readable over proprietary

Everything is YAML. Tracked file content sits byte-for-byte in the project, not a binary blob.

# state-driven over command-driven

You declare what should exist. EnvSetup works out how to reconcile the difference.

# safe over clever

By default, apply only fills in what's missing — it never overrides or removes anything on its own.

# correct over automatic

Discovery never guesses. Anything EnvSetup isn't confident about gets flagged for review, not silently included.

# small core, extensible ecosystem

The engine has no idea what a package or a dotfile is — that knowledge lives entirely in pluggable providers.

safety model

By default, apply only executes create actions — resources that are declared but missing. It still computes and shows update and delete actions in the plan, but skips running them.

Nothing overrides or removes configuration already on your machine unless you explicitly say so, every time.

  • --allow-updatelet it overwrite drifted resources
  • --allow-removelet it remove undeclared resources
  • --dry-runshow the plan without applying it

quickstart

01
$ envsetup scan

See what EnvSetup finds on this machine. Read-only, changes nothing.

02
$ envsetup init ~/dotfiles $ envsetup export ~/dotfiles

Create a project and populate it from what scan found. It's now a plain directory — put it under git.

03
$ envsetup plan $ envsetup apply

On another machine: see exactly what would change, then bring it in line with the project.

04
$ envsetup validate $ envsetup doctor

Check for drift later on, and diagnose common problems — broken symlinks, dead remotes, unavailable packages.
